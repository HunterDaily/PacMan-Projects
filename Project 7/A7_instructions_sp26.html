FAQ:

  1. Q: I'm getting a message about "pygame" not being found. What can I do about that?
    A: You'll need a package called "pygame", and will probably use "pip" to install it. Utilize your favorite search engine for more details!


  2. Q: I'm getting a bizarre error with pygame not being able to be installed and something about a wheel??
    A: pygame does not work on python 3.14 and newer. Install 3.13 or older and install pygame for that version of python instead


  3. Q: Ugh! I'm getting an unexpected indentation error but everything looks the same! What's going on?
    A: Python treats tabs and spaces differently, even though they may look the same to us! If you're using Notepad++, go to View->Show Symbol->Show White Space and TAB. This will put a small dot for a space, or an arrow for a tab so you can easily see the difference between the two. Other editors likely have something similar available to them.


  4. Q: Do I *have* to include an iterator?
    A: You do not need an iterator.


  5. Q: I have multiple versions of Python on my computer - which do I run?
    A: There are at least three different commands to run Python code: python game.py, python3 game.py, or py game.py. You can use "python --version", "python3 --version" or "py --version" to see which version you're running. My "python" and "python3" are both 3.10, while "py" is 3.11, and for me, pygame is installed under 3.11.


  6. Q: I see that the draw function is back under View again - I should just leave it there, right??
    A: Probably not! You will be porting your implementation of A4 over to Python (and adding the extra functionality from A6 for keeping track of score). You will likely find it easier to tell each Sprite to draw itself. You can have a default draw(...) function in Sprite that Tile, Fruit, and Pellet use (those are the basic draws with a single image), while Ms. Pacman and Ghosts can override that draw(...) function to do their fancy animation draw(...) instead (pulling from an array/list of images).

    Remember that these programming languages generally look for the most local version of the functions and variables available to them before going up the hierarchy and looking in parent classes. If you provide a draw function in Ms. Pacman, that's the one Ms. Pacman will use to draw herself, even if there's one in Sprite as well. If you don't provide a separate draw function in Tile, then when you tell the Tile to draw itself, it can't find one in its local class, so it will look at the Sprite parent class, find a draw function there, and use it to draw itself to the screen.
